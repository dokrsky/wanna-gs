# ADR-006: 경영주의 최근 변경 문맥과 실행 기록

- 상태: adopted · version 2 · 2026-09-21 · 구현/실행 검증 전
- 권한: user-delegated. 제안/조정자 main. 두 독립 검토와 반례 보완 재확인 후 UI-09 후보 범위에 채택했다. 사용자 직접 선택이나 현재 배포 동작으로 표시하지 않는다.
- policy_key: merchant.context_and_trace; effective_scope: UI-09 이후 `codex/ui-preview-20260921` 후보. 현재 배포 정책을 바꾸지 않는다.
- depends_on: ADR-003/005; supersedes/conflicts_with: 없음. CORE-05/06/23/25/26, AC-07/08/26/29/31, 05번 이전 변경/앞으로 지시, 07번 agent_runs를 구체화한다.
- 기준 base `e8a5b698186ef61432c296ab409614e59f4c7a33`. 적용 전 현재 DECISION_INDEX와 card.md를 확인한다. 실제 모델 판단·UI·기록을 연결하되 고객 동의와 경영주 최종 확인은 생략하지 않는다.

## 공백과 선택

현재 묶음 AI에는 선택/예산 현재값만 있고 ‘아까 뺀 것 다시’의 대상이 없다. 앞으로 지시도 안내문에서 멈추며 경영주 호출 이력은 새로고침 후 사라진다. 무제한 전체 대화를 보내거나 과거 거래를 되돌리는 대신 **최근 적용 변경 5개 + 명시 정책 초안 + 별도 실행 기록**으로 제한한다. 횟수 5는 데모의 단기 지시 문맥 상한이며 실제 GS 정책이 아니다. 새 화면 확인을 막는 전체 평가 선행조건은 추가하지 않는다.

## 초안 규칙

1. 현재 세션·세대·경영주 actor·점포·묶음 화면 안에서 실제 적용한 선택/이번 묶음 한도 변경만 최근 5개 기억한다. 수동 변경과 확인한 AI 변경을 동일 취급한다. 수동 예산 입력은 키마다 기록하지 않고 유효한 편집 완료(blur 또는 제출) 단위의 최초 전값·최종 후값을 한 변경으로 남긴다. AI 요청/발주 제출 전 진행 중인 유효 편집을 마무리하며 별도 승인 버튼은 늘리지 않는다. 필터만 변경·동일값·미적용 제안·실패는 복원용 이력을 만들지 않는다. 선택 추가/제외 집합과 전후 한도·순번만 사용하며 고객 원문/실명은 전달하지 않는다. 역할/점포 전환·reset·새로고침으로 단기 문맥은 끝나고 이를 화면에 표시한다. 영구 AI 이력을 자동으로 실행 문맥에 재주입하지 않는다.
2. ‘아까 뺀 것 다시’는 남아 있는 최근 5개 중 가장 최근의 제거 변경을 참조한다. 그 변경에서 제외한 ID를 **현재 선택에 합집합**으로 복원하며 이후 별도 추가한 선택을 지우지 않는다. ‘전전 변경’ 등 지시가 다른 대상을 뜻하면 특정 변경 ID를 명확히 식별하거나 한 번 확인한다. 원래 제거 대상 일부라도 현재 점포의 유효 미확보 후보가 아니면 조용한 부분 복원을 하지 않고 제외 사유/최신 확인을 요청한다. 과거 수량·조건·동의·발주·정책을 복원하지 않는다.
3. ‘아까 예산’은 가장 최근의 실제 이번 묶음 한도 변경의 이전 값을 초안으로 제시한다. 저장된 누적 정책 예산이나 사용액을 되돌리지 않는다. 기억 없음/모호함에는 확인 질문을 하고 현재값을 유지한다. 모델은 이력 참조·의도를 제안하고 코드가 ID/예산/현재 후보·snapshot을 검증한다. 적용 전에 전후값을 보여주고 경영주가 확인하며 발주 승인은 기존 별도 행동이다.
4. ‘앞으로도 이렇게’는 명확한 현재 선택 집합을 지속 정책의 **대상 집합 변경 초안**으로 전환한다. 기본적으로 ON/OFF와 누적 예산은 저장된 값을 유지하고 유지 여부를 명시한다. 빈 선택이거나 모호한 지시는 확인한다. 명시적으로 켜기/끄기·누적 예산을 지시했을 때만 해당 값을 변경 초안에 넣는다. 이번 묶음 한도/잔여 예산을 누적 예산으로 자동 복사하지 않으며 ‘앞으로 예산 2만원’처럼 기간이 불명확하면 누적 예산인지 확인한다. 현재 선택에서 대상 집합을 받은 정상 경로에는 상품명을 다시 타이핑하거나 두 번째 모델 호출을 의무화하지 않는다.
5. 지속 정책 초안은 기존 정책 전후 비교/최종 확인 경로를 재사용한다. 별도 미저장 수동 초안은 덮지 않는다. 이미 ON인 정책은 대상 변경 저장만으로 현재 수요도 발주될 수 있음을 보인다. policy version/점포/역할/세대 및 업무 조건이 바뀐 제안은 만료한다. 적용 시 UI 문맥 순번·참조 변경 ID·현재 선택·현재 시각의 유효 수요를 다시 확인한다. 부가기록만의 DB revision 증가는 업무 입력 동일성을 재검증한 뒤 기존 제안을 유지할 수 있으며 모델 재호출을 의무화하지 않는다. revision을 무조건 덮지 않고 실제 명령 시 최신 revision 검사도 유지한다. 제안 생성·화면 이동·실행 기록 저장으로 정책/발주를 실행하지 않는다.
6. 현재 묶음/정책의 실제 AI 시도마다 고유 run ID와 역할/점포·mode/model·요청 참조와 제한된 입력·검증된 출력·사용량·실제 경과시간을 브라우저 SQLite에 저장한다. 시도의 취소/낡음/중단, 관측한 모델 성공/오류, 화면/정책 적용 여부는 구분한다. 확정한 종료 상태를 늦은 응답으로 뒤집거나 이전 세대 기록을 새 세대로 옮기지 않는다. 미관측 사용량은 0이 아니라 unknown/null이다. 취소/늦은 응답은 적용하지 않는다. 서버 키·HTTP 인증·raw SDK 응답·내부 추론·다른 고객의 검색 원문은 저장하지 않는다. 모델 결과와 별개로 ‘화면 변경 적용/정책 저장’ 여부 및 관련 command ID를 추적하며 모델 성공을 거래 성공으로 취급하지 않는다. 기록은 해당 점포 경영주만 조회한다.
7. 기록 명령은 ADR-005의 부가 명령과 같이 정산/발주/결제/만료/업무 시계 이동을 실행하지 않는다. 동작별 키를 고정해 같은 저장 재시도를 중복 호출/실행으로 바꾸지 않는다. 로그 저장 실패와 모델/정책 저장 결과를 분리해 표시한다. 정책 적용 성공은 해당 명령 C의 committed receipt를 근거로 판단하며 확인할 수 없으면 결과 미확인으로 표시한다. C 성공이 확인되면 적용 기록 L만 재시도하고 성공한 정책을 재실행하지 않는다. 새 모델 재시도에는 새 run ID를 쓰고 이전 시도의 종료 상태를 보존한다.
8. 저장 스키마는 단일 작성자가 알려진 이전 schema/hash만 additive migration하고 기존 모든 거래/검색/니즈/추천 사건/보관 이력/receipt 원문·결과/clock을 보존한다. 저장 완료 전 새 상태를 publish하지 않으며 실패 재시도는 reset을 요구하지 않는다. 알 수 없는 버전이나 알려진 버전의 손상 사본은 거절하고 자동 초기화하지 않는다. 실제 카탈로그 크기의 유효 선택은 지원하고 20개를 넘는다는 이유로 정상 묶음을 통째로 막거나 조용히 자르지 않는다. 입력/출력 byte 상한·최대5 문맥은 명시적으로 검사한다.
