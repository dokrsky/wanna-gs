# ADR-003: 한 탭 데모의 보수적 거래 규칙

- 상태: proposed. 현재 UI Preview의 새 배포 선행조건이 아니며, 아래 정책을 사용하는 후속 거래 구현에 적용할 초안이다.
- 권한: user-delegated D-21. 조정자 제안, 2026-09-21, v1.
- 목적: 고객 요청을 공급·모의 결제·입고·48시간 픽업까지 연결하고 경영주는 묶음과 예외만 판단한다.
- 근거: card·CORE-01~14/23~26, D-41~46, 03/04/07/13/17/29번. 실제 GS 운영 규칙이 아닌 데모 설정이다. D-40 팀원 제안은 채택하지 않는다.
- context: `codex/ui-preview-20260921`, 기준 `18b0b31`, 현재 index의 ADR-001 adopted·ADR-002 proposed. policy_key=`demo_transactions_v1`, effective_scope=후속 UI-04 후보. depends_on=ADR-001; supersedes/conflicts_with=없음.

## 제안 규칙

| 항목 | 조건·경계·실패 동작 |
|---|---|
| 수량·가격 | 한 요청 1~20개 양의 정수, 정수 원. 판매가와 매입가 분리. 발주 금액은 매입가, 고객 결제는 동의한 판매가. 할인·쿠폰 없음. MOQ는 접수 상한이 아님. |
| 동의 | 체크 해제 기본. SKU·점포·수량·판매가·조건 버전·동의 시각을 기록. 구매 동의는 동의 시각부터 7일, `now >= consentExpiresAt`이면 결제 금지/재동의 필요. 결제 완료 후 이 기한은 예약/픽업을 만료시키지 않음. |
| 중복·수정 | 활성 동일 고객/점포/SKU 요청은 1건. 재전송은 같은 키/같은 본문일 때 기존 결과. 미발주/미배정에서 명시적 수량 변경·새 동의 허용: 감소는 순번 유지, 증가는 새 순번. 연결된 요청은 수량 변경을 막고 사유 표시. |
| 취소·재동의 | 모의 결제 전 명시적 취소 허용. 발주 연결/배정 해제는 같은 트랜잭션. 이미 제출한 발주 금액은 취소만으로 되돌리지 않음. 모든 동의 필드 변경·만료는 review_required로 결제 중단, 같은 SKU/점포의 최신 조건을 다시 확인·동의하면 새 순번으로 복귀. SKU/점포 변경은 기존 요청을 몰래 바꾸지 않고 별도 새 요청. |
| 유효 수요 | 동의 유효 pending 중 미배정/미예약/미취소 수량. review_required는 대기열을 막지 않고 신규 발주 합계에서 제외. 알림/추천/미식별·관심은 수요가 아님. |
| 보수적 발주 | 수동/자동 모두 초과발주 제외. 실행 직전 유효 수요에서 진행 중 연결량과 이미 확보한 미배정 물량을 제외한 부족분 이내. MOQ 이상·packSize 배수 중 한도 이하를 선택하고 남은 수요는 보존. 부족분이 조건 미달이면 보류. |
| FIFO·공급 | 세션+점포+SKU의 접수 순번. 요청 전량만 배정하며 앞의 유효 요청이 전량을 못 받으면 뒤 요청을 건너뛰지 않음. 공급은 주문 라인별 0~발주량으로 한 번 최종 확정, 같은/새 이벤트 키로 두 번 가산 금지. 부족분 연결 해제, 미배정 확보 잔량은 같은 점포/SKU 풀에 보존하고 다음 공급과 합산 가능. 원 공급 라인별 수량 출처 유지. |
| 배정·결제 | 물량 배정 및 조건 검증 후 같은 로컬 명령 안에서 모의 결제 결과 기록. 실패는 예약 성공 아님. 명시적 실패 시 배정 즉시 해제하고 review_required로 둠; 사용자가 실패 원인·조건을 확인하고 재시도할 때만 새 동의/새 순번으로 복귀. 자동 무한 재시도 없음. 결과 미확인 시 새 결제/물량 해제 대신 같은 명령 키 결과 조회. |
| 공급 잔량 | 취소/결제 실패의 해제량은 원 공급 라인별 잔량으로 돌려 FIFO에 사용. 일반 판매·폐기·환불·외부 재고로 전환하지 않음. 재고 총량=미배정+배정/예약+수령+픽업기한초과로 보존. |
| 입고 | 공급 확정량 전부를 라인별 한 번 입고. 분할/부족/초과 입고 제외. 배정된 모든 출처가 입고된 예약만 pickup_ready. 입고 재실행으로 시각/알림 재생성 금지. |
| 픽업 | 예약 확정 알림은 모의 결제 후, 픽업 알림은 입고 확인 후. 최초 픽업 알림 생성+정확히 48시간. `now < deadline`에만 해당 점포 경영주가 예약번호 일치·전량 1회 수령. 정각부터 만료, 예외 수령/환불/재판매 제외. |
| 예산·자동화 | 기본 꺼짐. 점포별 상품 대상·예산을 경영주가 확인·활성화. 예산은 초기화까지 누적 매입가 한도(일별 리셋 없음). 발주 승인과 금액 점유 원자 처리. 최종 공급 부족분 비용만 반납. 설정을 이미 쓴 금액 아래로 낮추지 못함. 상품 경쟁은 가장 오래된 유효 미연결 요청→SKU 순. 새 요청/조건·정책 변경/명시 실행 시 적용하며 앱 닫힌 동안 실행한다고 주장하지 않음. |
| 묶음·AI | 묶음 실행 전 현재 revision 대조, 하나라도 stale/조건 불일치면 전체 미실행·재검토. 자동 처리에는 새 건별 승인 없음. ‘이번만’은 현재 제안, ‘앞으로도’는 별도 정책 초안·명시 확인 후 적용. 금액/수량/실행은 로컬 도메인 서비스, LLM은 허용 필드 제안만. |
| clock·격리 | 업무 시각은 공통 clock `Date.now()+offset`이며 거래마다 한 번 고정. 이동은 앞으로 최대 30일/회, 역행 제외. 같은 origin의 한 탭 세션에서 역할을 전환. 세션/역할/경영주 점포 검사·revision·generation·명령 키 검증. reset은 현재 세션 명시 확인 후 원자 저장, 과거 모델 응답 폐기. 별도 실제 로그인/서버 거래 권한 없음. |

부분 배정·복잡한 분할 입고보다 전량/FIFO/한 번의 공급·입고가 설명과 검증이 단순하다. 잔량을 지우거나 수요 초과 신규발주로 숨기는 대안은 기각한다. 동의 무기한, 자동 결제 무제한 재시도, 입고 전 픽업 시간 시작도 기각한다.

## 독립 검토·채택

- 제품/범위: 미배정. 제안자 외 에이전트 1명.
- 상태/수량/실패: 미배정. 서로 다른 에이전트 1명.
- 반례·해결/채택 시각: 검토 후 기록. 현재 채택/검증 완료가 아니다.

## 구현·검증 연결

- 대상 O-01~09/12, R-01~11/13~27/38의 해당 거래 의미. O-10/11·품질 평가/외부 배포는 별도 작업이며 이 ADR로 완료하지 않는다.
- 채택 후 단일 `lib/domain/policy` 설정·SQLite 명령/제약·UI 동의/타임라인·시뮬레이터·seed·03/04/07 및 index를 함께 갱신한다. 현재 UI의 요청/승인만 있는 구조는 이전 중간 Preview로 보존한다.
- 정상: 요청→보수적 묶음 발주→확보/FIFO→모의 결제→입고→수령, 자동 정책 안의 추가 수요는 재승인 없이 처리.
- 경계: 3개 선두/2개 공급은 후순위 1개를 건너뛰지 않음; 추가 공급 합산; MOQ 초과 접수; pack 맞추려 초과 금지; 동의 7일 정각/픽업 48시간 정각; 예산 정확 일치.
- 실패: 취소/결제 실패 잔량 보존, 가격 변경 재동의, stale 묶음 전체 중단, 중복 공급/입고/수령, 저장 실패 이전 snapshot 보존, reset 중 늦은 응답, 다른 역할/점포 거절.
- 독립 QA·G1~G6는 구현 후 수행(D-46). PR #1의 작은 후속 구현/배포 증거와 최종 검증을 구분한다.
